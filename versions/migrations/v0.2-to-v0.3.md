# OKF v0.2 → v0.3

공식 v0.3 명세의 변경 중 기존 번들과 Mekra 운영에 영향을 주는 항목만 요약합니다. 세부 규칙의 정본은 [공식 SPEC §13](https://github.com/open-knowledge-format/open-knowledge-format/blob/527e81aff55992be21507e97004286789126f88c/SPEC.md#13-changes-from-v02)입니다. 공식 저장소는 [open-knowledge-format/open-knowledge-format](https://github.com/open-knowledge-format/open-knowledge-format)으로 옮겨졌습니다.

v0.2 번들은 그대로 유효합니다. v0.3은 대부분 v0.2의 설명을 명확히 하며, 아래 두 가지만 기존 값을 읽는 방식을 바꿉니다. 전환할 이득이 있을 때 아래 순서로 확인하고, `okf_version`은 마지막에 바꿉니다.

## 읽는 방식이 바뀌는 두 가지

| 변경 | 기존 번들에 미치는 영향 | 확인할 것 |
| --- | --- | --- |
| `/`로 시작하지 않는 경로 필드는 그 값을 담은 파일의 디렉터리에서 해석합니다. | v0.2 예시처럼 번들 루트 기준으로 쓴 `resource`·`sources[].resource`·`computation` 등의 상대 경로가 하위 디렉터리 파일에서 다른 대상을 가리키거나 깨질 수 있습니다. v0.2 이하 또는 버전을 선언하지 않은 번들에서는 소비자가 루트 기준 해석을 대신 시도할 수 있지만, `"0.3"`을 선언하면 이 보완이 사라집니다. | 하위 디렉터리 개념의 경로 필드 값을 찾아 파일 기준과 루트 기준으로 각각 해석해 봅니다. 루트 기준이 맞다면 값 앞에 `/`를 붙입니다. 두 위치에 같은 이름의 파일이 있으면 깨진 링크 없이도 대상이 바뀔 수 있으니 실제 대상을 비교합니다. Markdown 본문 링크는 v0.2에서도 파일 기준이었습니다. |
| 신뢰 등급은 `generated.at` 이후(같은 시각 포함)의 검증만으로 계산합니다. | 내용을 바꾼 뒤 다시 확인하지 않은 개념은 human-reviewed에서 더 낮은 등급으로 내려갈 수 있습니다. | 등급이 내려가는 것은 안전한 방향입니다. 실제로 다시 확인하지 않았다면 검증 시각을 옮기거나 새 검증 기록을 만들지 않습니다. 다시 확인해야 할 개념만 골라 실제로 확인합니다. |

## 명확해진 규칙

- **개념 판정:** `index.md`와 `log.md`는 모든 깊이에서 예약 파일입니다. 그 밖의 `.md`는 frontmatter에 비어 있지 않은 `type`이 있을 때만 개념입니다. `type`이 없는 `README.md`·`AGENTS.md` 같은 문서는 개념이 아니며 적합성을 해치지 않습니다. `.md`가 아닌 파일은 자산이고, `.`으로 시작하는 파일과 디렉터리는 번들에 속하지 않습니다.
- **번들 밖 경로:** 번들 루트 밖으로 해석되는 링크와 경로는 외부 참조이며, 엄격한 소비자는 로컬 파일시스템에서 읽지 않습니다. 저장소 전체를 읽는 에이전트에게는 탐색 경로가 되지만, 번들만 따로 쓰면 그 대상은 없습니다.
- **frontmatter:** YAML 1.2 core schema를 따르고 중복 키를 허용하지 않습니다. 숫자나 불리언처럼 보이는 문자열 값은 따옴표로 감쌉니다(`okf_version: "0.3"`).
- **타임스탬프:** 오프셋이 있는 date-time이나 날짜만 쓰며, 날짜만 쓴 값은 그날 UTC 0시입니다. 오프셋 없는 date-time은 유효하지 않습니다.
- **수명주기:** `status`가 없으면 `stable`입니다. 목록(`draft`·`stable`·`deprecated`)에 없는 값은 `stable`로 취급되지 않으며, 현재 지식만 거르는 소비자에게서 빠집니다. `stale_after`는 "다시 확인할 때"를 뜻하며 읽을 수 없는 값은 최신으로 취급되지 않습니다.
- **관계:** 링크는 방향은 있지만 종류가 정해지지 않은 관계입니다. 형식이 정해진 관계(typed relationships)는 v0.3 표준이 아닙니다.

## 선택적으로 도입할 수 있는 항목

- **`superseded_by`:** `status: deprecated`와 함께 대체 개념의 경로를 가리킵니다. 개념을 옮기거나 이름을 바꿀 때 옛 경로에 짧은 deprecated 개념을 남기면 기존 참조가 이어집니다. 일반적인 관련 문서는 본문 링크로 둡니다.
- **번들 메타데이터:** 번들 루트 `index.md`의 frontmatter에 `title`·`description`·`license`와 확장 키를 둘 수 있습니다. 하위 `index.md`에는 frontmatter를 두지 않습니다. 인덱스를 재생성하는 도구는 기존 루트 frontmatter를 보존해야 합니다. 이름과 선택 범위가 실제로 있을 때만 채우고, 근거가 없는 `license`는 빈 값 대신 키를 생략합니다.
- **확장 키:** 알 수 없는 키는 모든 수준에서 보존해야 하며, 앞으로 공식 명세는 `x-`로 시작하는 키를 정의하지 않습니다. Mekra 고유 정보가 필요하면 `x-mekra-` 같은 접두를 쓸 수 있지만, 실제 사용처가 생기기 전에는 추가하지 않습니다.

## 함께 쓰는 도구 확인

v0.3을 아직 지원하지 않는 도구가 있습니다. 2026-11-23 현재 Google Knowledge Catalog의 `kcmd`는 공개된 v0.2 범위로 OKF를 지원하며, `bundle/` 안에 `type`이 없는 `.md`가 있으면 push를 거부합니다. 이런 도구와 번들을 주고받아야 한다면 `okf_version: "0.2"`를 유지하고 모든 Markdown에 `type`을 두는 구성을 계속 사용할 수 있습니다. 도구의 지원 판본은 사용할 때 다시 확인합니다.

## Mekra 템플릿과 이 가이드

Mekra의 [템플릿 번들](../../templates/mekra/index.md)과 이 가이드의 [운영 지식](../../okf/index.md)은 v0.3을 선언합니다. 두 번들은 경로 필드에 URL만 쓰고 신뢰 필드를 쓰지 않아, 링크 해석과 신뢰 등급이 v0.2와 같습니다. Mekra가 구성하는 번들에서는 frontmatter를 둔 문서를 개념으로 보고 `type`을 반드시 적습니다. 이는 개념으로 쓰려던 문서가 `type` 누락으로 빠지지 않게 하는 작성 관례이며 명세의 요구가 아닙니다. 판단 근거는 [OKF의 역할과 활용](../../okf/okf-format.md)에 있습니다.

## 점검

- 하위 디렉터리 개념의 경로 필드가 파일 기준 해석에서 의도한 대상을 가리키는가?
- 내용을 바꾼 개념의 검증 기록을 실제 재확인 없이 갱신하지 않았는가?
- 목록 밖의 `status` 값이 의도와 달리 현재 지식에서 빠지지 않는가?
- 함께 쓰는 도구가 v0.3과 `type` 없는 Markdown을 읽는가?
- 위를 확인한 뒤 bundle-root `index.md`의 `okf_version`을 `"0.3"`으로 바꿨는가?
