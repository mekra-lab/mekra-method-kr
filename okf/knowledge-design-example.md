# 같은 주문 지식의 통합·분화·조합

[설계 탐색과 충분성](knowledge-design.md)의 비교를 실제 본문 형태로 설명하는 가상 예시다. 아래 파일명·유형·분량은 고정 템플릿이 아니다. 세 안 모두 같은 규칙을 보존하며, 어느 안의 성능이 더 좋다는 실험 결과를 뜻하지 않는다.

## 가상 원자료

원자료 `rules.md`를 다음처럼 가정한다. 규칙을 정의하고 변경하는 책임은 이 문서에 있고, OKF 본문은 각 개념의 관점에서 의미를 내재화한다. 아래 코드 블록은 예시 파일의 내용이다. 각 안의 디렉터리 밖에 같은 `rules.md`가 있으며, 각 번들의 `index.md`에는 `okf_version: "0.2"`를 선언하고 해당 개념을 연결한다고 가정한다.

```markdown
# 주문 운영 규칙

1. 출고 확정 전에는 주문 취소를 접수할 수 있다. 출고 확정 후에는 접수할 수 없다.
2. 접수된 취소는 결제 전이면 환불 없이 완료한다.
3. 결제 후이면 환불 성공으로 취소를 완료한다.
4. 환불이 실패하면 취소는 미완이며 환불 처리가 남는다.
5. 현재 재고 예약은 취소 접수 시 즉시 해제한다. 환불 실패여도 해제 상태를 유지한다.
```

여기서 취소의 접수, 취소 완료, 재고 해제는 같은 상태가 아니다. 이 차이가 사라지면 파일 수와 무관하게 필요한 지식을 잃는다.

## 통합안

`integrated/cancellation.md` 하나에서 전체 조건을 읽는다.

```markdown
---
type: Rule
title: 주문 취소
---

# 주문 취소

출고 확정 전에는 취소를 접수할 수 있으며, 확정 후에는 접수할 수 없다.
접수한 취소는 결제 전이면 환불 없이 완료하고, 결제 후이면 환불 성공으로 완료한다.
환불에 실패하면 취소는 미완이며 환불 처리가 남는다.

재고 예약은 취소 접수 시 즉시 해제한다. 환불 실패여도 해제 상태를 유지하므로,
재고가 해제됐다는 사실만으로 취소가 완료됐다고 판단하지 않는다.

정의와 변경 기준은 [주문 운영 규칙](../rules.md)이다.
```

취소 전체를 이해할 때 조건을 한곳에서 확인할 수 있다. 재고만 질문하거나 수정할 때도 같은 문서가 대상이 된다.

## 분화안

`split/eligibility.md`, `split/refund.md`, `split/inventory.md`로 나눈다. 각 문서는 자신의 판단을 이해할 조건을 설명하고, 다른 개념으로 넘어가는 이유를 연결한다.

`split/eligibility.md`:

```markdown
---
type: Rule
title: 취소 접수 조건
---

# 취소 접수 조건

출고 확정 전에는 취소를 접수할 수 있으며, 확정 후에는 접수할 수 없다.
접수 가능 여부와 처리 완료는 다르다. 접수 후 결제 전이면 환불 없이 완료하고,
결제 후이면 환불 성공을 기다린다. 실패 시 미완으로 남는 의미는
[결제와 환불](refund.md)에서 설명한다.

접수된 취소는 [재고 예약 해제](inventory.md)의 대상이다.
재고 해제와 취소 완료는 별도로 판단한다.
정의와 변경 기준은 [주문 운영 규칙](../rules.md)이다.
```

`split/refund.md`:

```markdown
---
type: Rule
title: 결제와 환불
---

# 결제와 환불

출고 확정 전에 접수된 취소를 다룬다. 결제 전이면 환불 없이 취소를 완료한다.
결제 후이면 환불 성공으로 완료하며, 환불 실패는 미완 상태와 남은 환불 처리를 뜻한다.
출고 확정 후에는 취소 자체를 접수할 수 없으므로
[접수 조건](eligibility.md)을 먼저 구분한다.

환불 실패가 재고 예약의 유지까지 뜻하지는 않는다.
재고 해제 시점은 [재고 예약](inventory.md)의 조건으로 따로 판단한다.
정의와 변경 기준은 [주문 운영 규칙](../rules.md)이다.
```

`split/inventory.md`:

```markdown
---
type: Rule
title: 재고 예약 해제
---

# 재고 예약 해제

출고 확정 전에 취소를 접수하면 재고 예약을 즉시 해제한다.
환불 실패여도 해제 상태를 유지한다. 다만 결제 후 환불이 실패한 취소는 미완이므로,
재고 해제를 근거로 취소 완료를 표시하지 않는다.

[취소 접수 조건](eligibility.md)은 해제의 대상이 되는 주문을 구분하고,
[결제와 환불](refund.md)은 재고 해제와 별개인 취소 완료 조건을 설명한다.
정의와 변경 기준은 [주문 운영 규칙](../rules.md)이다.
```

재고 문서를 단독으로 읽어도 적용 대상·시점·예외와 취소 완료의 차이를 알 수 있다. 반면 전체 처리를 상세히 검토할 때는 개념 사이를 이동해야 한다. 각 문서의 설명은 같은 원자료에서 파생되므로 규칙이 바뀌면 관련 재서술도 함께 검토한다.

## 조합안

`combined/`에는 분화안의 세 개념을 같은 내용으로 두고 `cancellation-flow.md`를 추가한다. 종합 설명은 독립된 규칙 정본이 아니라 함께 작용하는 조건을 설명한다.

```markdown
---
type: Concept
title: 취소 처리의 전체 흐름
---

# 취소 처리의 전체 흐름

[접수 조건](eligibility.md)에 따라 출고 확정 전의 취소를 접수한다.
접수 시 [재고 예약](inventory.md)을 즉시 해제한다.
[결제와 환불](refund.md)에 따라 결제 전에는 환불 없이 완료하고,
결제 후에는 환불 성공을 기다린다. 환불 실패라면 재고는 해제됐어도 취소는 미완이다.

따라서 전체 처리 상태를 볼 때 접수 가능 여부, 재고 해제와 취소 완료를 구분한다.
규칙의 정본은 [주문 운영 규칙](../rules.md)이며,
각 개념의 조건이 바뀌면 이 종합 설명의 순서와 상태 해석도 다시 살핀다.
```

전체 질문은 종합 설명에서 시작하고, 재고의 조건만 필요하면 개별 개념에서 시작할 수 있다. 그만큼 변경 시 종합 설명까지 유지해야 한다.

## 같은 질문으로 읽기

질문은 “출고 확정 전에 취소를 접수했고 결제 후 환불에 실패했다. 재고 예약과 취소 상태는 무엇인가?”다. 세 안 모두 **재고 예약은 해제됐고, 취소는 미완이며 환불 처리가 남는다**고 해석해야 한다.

| 구성 | 답을 뒷받침하는 경로 | 살필 차이 |
| --- | --- | --- |
| 통합 | `cancellation.md`의 접수·환불·재고 조건 | 한 문서에 답의 근거가 있으나 개별 판단만 필요해도 같은 문서를 읽는다 |
| 분화 | `inventory.md`의 예외와 상태 구분, 필요하면 `refund.md`의 완료 조건 | 개별 개념에도 핵심 맥락이 있으며 환불 상세로 직접 이어진다 |
| 조합 | `cancellation-flow.md`의 전체 상태, 필요하면 각 개념 | 전체 설명과 개별 탐색을 선택할 수 있으나 재서술의 유지 책임이 늘어난다 |

출고 확정 후의 요청이라면 세 안 모두 접수 불가를 먼저 판단해야 한다. 환불·재고 문서부터 읽더라도 그 전제를 놓치지 않는지 살필 수 있다. 이 표는 문서 내용에 따른 읽기 예시이며 에이전트의 실제 읽기 기록이나 측정 결과가 아니다.

## 같은 변경을 반영하기

원자료의 5번 규칙이 다음처럼 바뀌었다고 가정한다. 나머지 규칙은 유지한다.

> 결제 전 취소는 접수 시 재고 예약을 해제한다. 결제 후 취소는 환불 성공 시 해제하고, 환불 실패 시 예약을 유지한다.

통합안은 `cancellation.md`의 재고 조건과 상태 설명을 바꾼다. 분화안은 `inventory.md`의 조건과 `refund.md`의 “환불 실패가 재고 예약의 유지까지 뜻하지는 않는다”는 설명을 함께 바꾼다. 후자는 이제 “환불 실패 시 취소는 미완이며 재고 예약도 유지된다”가 된다. `eligibility.md`는 해제 시점을 직접 규정하지 않아 이 변경으로 수정할 문장은 없지만, 그 판단은 내용을 읽어 확인한다. 조합안은 이 검토에 더해 `cancellation-flow.md`의 즉시 해제와 환불 실패 설명도 갱신한다.

변경 뒤 분화안·조합안의 `inventory.md`에서 핵심 설명은 다음과 같이 된다.

```markdown
출고 확정 전에 접수된 취소에서 결제 전이면 재고 예약을 즉시 해제한다.
결제 후이면 환불 성공 시 해제하고, 환불 실패 시에는 예약을 유지한다.
환불 실패인 취소는 미완이며 환불 처리와 재고 예약 해제가 남는다.
```

조합안의 종합 설명도 “접수 시 즉시 해제” 대신 결제 상태에 따른 해제 시점을 설명해야 한다. 같은 질문의 새 답은 **재고 예약이 유지되고, 취소는 미완이며 환불 처리와 재고 예약 해제가 남는다**이다. 정본 수정, 관련 의미의 갱신과 변경 후 질문의 해석을 함께 확인한다. 수정한 파일 수가 적다는 사실만으로 더 좋은 구성이라고 판정하지 않는다.

## 선택한 구성을 이어가기

어떤 안을 선택할지는 실제 질문과 변경 양상에 달려 있다. 재고 질문이 잦아 분화안을 선택했다면 다음처럼 관련 운영 맥락에 이유를 남길 수 있다.

> 재고의 조건을 독립적으로 조회·갱신하는 일이 많아 취소 접수·환불·재고를 분리했다. 각 개념에는 출고 확정과 취소 완료의 차이를 유지한다. 전체 취소 흐름을 반복해서 조립하는 부담이 커지면 종합 설명의 추가를 검토한다.

이는 [설계 선택의 인계](knowledge-operation.md#설계-선택의-인계) 예시다. 실제 관찰이 없는 상황에서 “잦다”는 이유를 만들어 기록하지 않는다. 가정에 근거해 선택했다면 그 가정과 확인할 조건을 남긴다. 분화가 계속 유리하다면 더 세분화한 안도 검토하고, 통합이 유리하다면 함께 읽을 범위를 넓혀 [탐색 경계](knowledge-design.md#탐색-범위의-확장과-마무리)를 다시 살핀다.
