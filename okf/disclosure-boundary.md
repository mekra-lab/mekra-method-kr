# 정보 접근과 외부 공개의 경계

## 문제

에이전트가 어떤 정보에 접근할 수 있다는 사실만으로 그 정보나 그로부터 얻은 맥락을 외부에 공개할 권한까지 생기는 것은 아니다.

내부 분석, 피드백 작성, 배포 검토, 개인화된 지원처럼 넓은 맥락을 읽어야 좋은 판단을 할 수 있는 작업에서도 실제 외부 전송의 대상과 범위는 별도로 결정해야 한다.

## 선택

정보를 읽고 내부 판단에 사용하는 범위와 외부 메시지·문서·이슈·API·공개 저장소 등에 공개하거나 전송하는 권한을 구분한다.

외부 행동에서는 목적, 수신자, 공개 범위와 사용자가 이미 부여한 권한을 기준으로 필요한 정보만 사용한다. 접근 가능한 전체 맥락을 자동으로 전달 범위로 간주하지 않는다.

이미 해당 목적과 범위에 대한 권한이 명확하다면 같은 결정을 기계적으로 다시 확인할 필요는 없다. 반대로 내부 접근 권한이나 작업 자율성만으로 새로운 외부 공개 권한을 추론하지 않는다.

문서와 개념의 연결은 실제 접근 권한을 설정하지 않는다. 사용자별 문서·관계의 접근 차단과 탐색 결과 제한은 저장소·파일 시스템·서비스 등 실제 운영 시스템이 맡는다. 이 원칙을 지식에 기록한 범위와 해당 통제를 구현·확인한 범위는 [실제 사용 연결](adoption.md#지식-구성과-실제-사용의-연결)에서도 구분한다.

## 제목·관계와 파생 표현

공개 범위는 본문뿐 아니라 제목·파일명·링크와 관계 설명이 드러내는 정보에도 적용한다. 예를 들어 제한된 계획 문서의 본문을 읽을 수 없더라도, 공개 문서의 링크 이름만으로 그 계획의 존재가 드러날 수 있다. 연결을 남길 때도 수신자에게 허용된 정보의 범위를 살핀다.

요약·재서술·일반화한 파생 표현도 실제로 드러내는 의미를 기준으로 공개 범위를 확인한다. 원문을 그대로 복사하지 않았다는 사실만으로 공개 가능한 내용이 되지는 않는다. 필요한 맥락을 전달하면서 식별정보나 제한된 사실·관계를 드러내는지 판단한다. 근거를 추적하기 위해 덧붙인 출처 경로도 같은 범위에서 살핀다.

## 적용 판단

- 내부 판단에 필요한 정보와 실제 산출물에 노출해야 하는 정보가 같은가?
- 공개 또는 전송의 목적과 수신자가 현재 권한 범위에 포함되는가?
- 민감하거나 식별 가능한 맥락을 그대로 전달할 필요가 있는가, 의미를 보존하며 일반화할 수 있는가?
- 새로운 공개 범위를 만드는 행동이라면 그 권한이 명확한가?

[적용 경험의 환류](feedback.md)에서는 유용한 피드백을 판단하고 초안을 만드는 재량과 실제 전송 권한을 구분한다. [연구와 다국어 배포](distribution.md)에서는 파일 경로나 공통 정본이 같더라도 각 변경 내용의 공개 적합성을 다시 판단한다.
