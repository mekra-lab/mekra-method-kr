# Templates

이 템플릿은 [Open Knowledge Format](https://github.com/GoogleCloudPlatform/open-knowledge-format)을 활용하기 위한 자체 운영 예시입니다. 형식은 공식 명세를 따르고, 구조와 지침은 각 저장소의 목적에 맞게 조정합니다. 적용 버전과 명세 기준점은 [현재 버전 기준](../versions/current.md)을 참고합니다.

실제 저장소에 복사한 뒤 불필요한 항목을 지우고 고유 문맥을 추가하는 최소 템플릿입니다.

이 README를 포함한 `templates/` 아래의 모든 파일은 [CC0-1.0](LICENSE)으로 제공합니다. 복사·수정·통합할 때 Mekra Method 출처 표시나 라이선스 사본 유지를 이용 조건으로 요구하지 않습니다. 적용 기준을 기록할지는 사용자가 선택합니다. CC0는 제3자의 권리나 상표·특허 등의 권리를 없애지 않습니다.

- [`AGENTS.md.template`](AGENTS.md.template): 루트 `AGENTS.md`에 합치는 **MEKRA 진입점 연결과 선택적 저장소 운영 선호 절**
- [`MEKRA.md.template`](MEKRA.md.template): 지식의 목적·범위·진입점·참고 기준과 운영 맥락을 담는 선택적 진입점
- [`okf/index.md`](okf/index.md): OKF 번들 루트 예시
- [`okf/concept.md`](okf/concept.md): 최소 개념 문서 예시

`concept.md`는 최소 예시를 유지하며, 필요한 경우 적용 중인 OKF 명세의 기능을 선택할 수 있다는 짧은 작성 힌트를 담습니다. 예시에 나온 필드가 사용 가능한 범위 전체를 뜻하지는 않습니다. 명세의 참조 경로와 이 저장소의 기준점은 위의 현재 버전 기준에서 확인합니다.

이곳의 `okf/`는 예시 번들을 담은 폴더명입니다. 적용 대상에서는 `knowledge/`처럼 다른 이름을 쓰거나 저장소 루트를 번들로 사용할 수 있습니다. 선택한 번들 위치에 `okf/` 안의 파일을 복사하고, 지침과 링크도 그 위치에 맞춥니다. `okf/`라는 바깥 폴더까지 그대로 복사할 필요는 없습니다. 위치 선택의 근거는 [적용 판단](../okf/adoption.md#번들-위치와-기존-구조)에 있습니다.

## 진입점 구성 선택

두 구성 중 대상에 맞는 하나를 선택합니다. `MEKRA.md`는 Mekra Method의 선택적 운영 예시이며 공식 OKF 필수 파일이 아닙니다. 선택의 근거는 [지식 운영 진입점](../okf/adoption.md#지식-운영-진입점)에 있습니다.

- **분리 구성:** 기본 예시에서는 `MEKRA.md.template`을 저장소 루트 `MEKRA.md`로 복사하고, `AGENTS.md.template`의 필요한 절을 기존 루트 `AGENTS.md`에 합칩니다. 지식의 목적·범위와 운영 맥락은 `MEKRA.md`에 두며, AGENTS에서는 읽도록 연결합니다.
- **AGENTS만 사용하는 구성:** `MEKRA.md.template`의 필요한 내용을 기존 `AGENTS.md`의 `OKF 지식 운영` 절에 합칩니다. `# Mekra` 제목은 생략하고 하위 제목의 깊이를 맞춥니다. AGENTS 템플릿의 첫 문장인 `MEKRA.md` 읽기 안내는 생략하며, 나머지 적용 범위 설명은 유지합니다. 별도 `MEKRA.md` 파일은 만들지 않습니다.

번들과 운영 맥락을 독립적으로 복사·배포한다면 `MEKRA.md`를 번들 루트에 둘 수 있습니다. 예를 들어 `knowledge/MEKRA.md`에 두면 AGENTS의 링크는 `knowledge/MEKRA.md`, MEKRA의 지식 탐색 링크는 `index.md`로 바꿉니다. 저장소 자체가 번들이면 두 루트가 같습니다. 번들 안의 `MEKRA.md`는 개념 문서 형식을 따라야 하므로 맨 앞에 다음 frontmatter를 추가합니다. `Playbook`은 운영 안내를 위한 타입 예시입니다. 위치와 형식의 근거는 [지식 운영 진입점](../okf/adoption.md#지식-운영-진입점)에 있습니다.

```yaml
---
type: Playbook
---
```

저장소 전체를 번들로 사용하는 경우에는 같은 번들에 포함하는 `AGENTS.md` 등 다른 운영 Markdown에도 이 형식 규칙이 적용됩니다.

기존 저장소 지침과 고유 선택을 보존하고, 옮긴 운영 설명은 한곳에서 관리합니다. 이미 운영 원칙을 담은 개념이 있다면 진입점에서 연결하고 템플릿의 일반 설명을 줄입니다. 적용 기준을 남길 때는 [실제 참고 기준](../versions/README.md#실제-참고-기준을-남길-때)을 따릅니다. 템플릿에는 확인되지 않은 릴리스 번호를 미리 채우지 않습니다.

지식 운영의 자율 판단 원칙은 OKF 지식 운영 범위에 적용합니다. 선택적 `저장소 운영 선호` 절은 그 내용이 명시한 저장소 전체 후속 작업 범위에 적용되도록 `OKF 지식 운영`과 동급 절로 둡니다. 적용 후에는 실제 진입 지침에서 지식 번들로 이어지는 링크를 확인합니다.

템플릿을 그대로 유지하는 것이 목표가 아닙니다. 대상의 실제 자료와 관련 [facet](../facets/README.md), OKF 지식을 보고 필요한 구조만 남깁니다.

기존 OKF를 갱신할 때는 템플릿 파일로 덮어쓰지 않고 기존 지식과 고유 지침을 보존하며 유효한 개선을 합칩니다. [적용 판단](../okf/adoption.md)에 따라 이번 범위를 정하고, [적용 안내](../APPLICATION.md)에 따라 이후의 자료 투입 위치와 반영 방법을 대상 저장소에 남깁니다. 사용자용 안내는 대상 README 등에 두고, 에이전트에게도 필요한 고유 선택은 선택한 지식 운영 진입점에서 연결합니다.
