# Templates

이 템플릿은 Mekra Method의 운영 예시이며, 지식의 표현에는 [Open Knowledge Format](https://github.com/GoogleCloudPlatform/open-knowledge-format)을 사용합니다. 형식은 공식 명세를 따르고, 구조와 지침은 각 저장소의 목적에 맞게 조정합니다. 적용 버전과 명세 기준점은 [현재 버전 기준](../versions/current.md)을 참고합니다.

실제 저장소에 복사한 뒤 불필요한 항목을 지우고 고유 문맥을 추가하는 최소 템플릿입니다.

어떤 템플릿이 필요한지는 [적용 안내](../APPLICATION.md)에서 대상과 범위를 살펴 판단합니다. Method의 [운영 원칙](../PRINCIPLES.md)과 상세 개념은 판단 근거이며, 그 문서나 가이드 저장소의 배치를 적용 대상에 그대로 복사하도록 요구하지 않습니다.

이 README를 포함한 `templates/` 아래의 모든 파일은 [CC0-1.0](LICENSE)으로 제공합니다. 복사·수정·통합할 때 Mekra Method 출처 표시나 라이선스 사본 유지를 이용 조건으로 요구하지 않습니다. 적용 기준을 기록할지는 사용자가 선택합니다. CC0는 제3자의 권리나 상표·특허 등의 권리를 없애지 않습니다.

- [`AGENTS.md.template`](AGENTS.md.template): 루트 `AGENTS.md`에 합치는 **MEKRA 진입점 연결과 선택적 저장소 운영 선호 절**
- [`mekra/MEKRA.md`](mekra/MEKRA.md): 개별 Mekra의 목적·범위·탐색 경로·참고 기준과 운영 맥락을 담는 공통 진입점
- [`MEKRAS.md.template`](MEKRAS.md.template): 여러 Mekra를 함께 사용하는 환경의 발견 인덱스 예시
- [`mekra/index.md`](mekra/index.md): 기본 디렉터리 이름을 사용하는 OKF 번들 루트 예시
- [`mekra/concept.md`](mekra/concept.md): 최소 개념 문서 예시

`concept.md`는 최소 예시를 유지하며, 필요한 경우 적용 중인 OKF 명세의 기능을 선택할 수 있다는 짧은 작성 힌트를 담습니다. 예시에 나온 필드가 사용 가능한 범위 전체를 뜻하지는 않습니다. 명세의 참조 경로와 이 저장소의 기준점은 위의 현재 버전 기준에서 확인합니다.

새 파일 기반 Mekra를 별도 디렉터리에 구성할 때는 `mekra/`를 기본 위치로 사용합니다. 이곳의 `mekra/`는 그 기본값을 사용하는 OKF 예시 번들입니다. 기존 정본 위치나 대상에 더 적합한 구조가 있으면 그 위치를 따르며, `knowledge/`처럼 다른 이름이나 저장소 루트를 번들로 사용할 수 있습니다. 선택한 번들 위치에 `mekra/` 안의 파일을 복사하고, 지침과 링크도 그 위치에 맞춥니다. 위치 선택의 근거는 [적용 판단](../okf/adoption.md#번들-위치와-기존-구조)에 있습니다.

## 진입점 구성 선택

개별 Mekra의 진입점과 환경의 발견 경로를 맞춥니다. `MEKRA.md`와 `MEKRAS.md`의 역할은 Mekra의 운영 방식이며 공식 OKF 필수 파일 규칙이 아닙니다. 판단 근거는 [지식 운영 진입점](../okf/adoption.md#지식-운영-진입점)과 [여러 Mekra의 발견 인덱스](../okf/adoption.md#여러-mekra의-발견-인덱스)에 있습니다.

- **저장소 안에 별도 Mekra:** `mekra/` 예시 파일을 대상의 `mekra/` 또는 실제로 선택한 위치에 복사합니다. `MEKRA.md`는 그 Mekra와 함께 놓고, `AGENTS.md.template`의 필요한 절을 기존 AGENTS에 합쳐 연결합니다.
- **저장소 전체가 하나의 Mekra:** `MEKRA.md`를 저장소 루트에 두고 AGENTS에서 직접 연결합니다. MEKRA의 지식 탐색 링크는 실제 `index.md`나 `okf/index.md` 등으로 맞춥니다. 모든 지식을 같은 디렉터리 안으로 옮길 필요는 없습니다.
- **여러 Mekra를 함께 사용하는 환경:** 환경 루트 등 접근 가능한 위치에 `MEKRAS.md.template`을 `MEKRAS.md`로 복사하고 실제 Mekra들의 이름·짧은 설명·진입점 링크를 채웁니다. AGENTS의 첫 문장을 인덱스를 읽고 관련 Mekra로 이동하는 안내로 바꿉니다. 하나만 사용하는 환경은 MEKRA로 직접 연결합니다.

기본 예시의 연결은 `AGENTS.md → mekra/MEKRA.md → index.md`입니다. 여러 Mekra를 쓰는 구성에서는 `AGENTS.md → MEKRAS.md → 관련 MEKRA.md`로 연결합니다. 구조를 바꾸면 관련 진입점과 인덱스 링크도 함께 갱신합니다.

번들 안의 `MEKRA.md`는 개념 문서 형식을 따릅니다. 제공한 예시에는 다음 frontmatter가 이미 있으며, `Playbook`은 운영 안내를 위한 타입 선택입니다. OKF 번들 밖으로 진입점을 옮기면 그 위치에 같은 형식 의무가 생기는 것은 아닙니다.

```yaml
---
type: Playbook
---
```

저장소 전체를 OKF 번들로 사용하는 경우에는 같은 번들에 포함하는 `AGENTS.md`나 `MEKRAS.md` 등 다른 운영 Markdown에도 개념 문서의 형식 규칙이 적용됩니다.

기존 AGENTS의 지식 운영 절로 시작했다면 유효한 설명을 `MEKRA.md`로 옮기고 AGENTS에는 연결과 저장소 전체 운영 지침을 남깁니다. 기존 진입점은 새 파일을 중복 생성하기 전에 목적·범위와 위치를 확인합니다. 이미 운영 원칙을 담은 개념이 있다면 진입점에서 연결하고 템플릿의 일반 설명을 줄입니다. 적용 기준을 남길 때는 [실제 참고 기준](../versions/README.md#실제-참고-기준을-남길-때)을 따릅니다. 템플릿에는 확인되지 않은 릴리스 번호를 미리 채우지 않습니다.

템플릿의 자율 판단 안내는 지식의 작성·갱신과 관련 변경의 반영에 적용합니다. 선택적 `저장소 운영 선호` 절은 그 내용이 명시한 저장소 전체 후속 작업 범위에 적용되도록 `지식 운영`과 동급 절로 둡니다. 적용 후에는 실제 진입 지침에서 지식 번들로 이어지는 링크를 확인합니다.

템플릿을 그대로 유지하는 것이 목표가 아닙니다. 대상의 실제 자료와 관련 [facet](../facets/README.md), OKF 지식을 보고 필요한 구조만 남깁니다.

기존 OKF를 갱신할 때는 템플릿 파일로 덮어쓰지 않고 기존 지식과 고유 지침을 보존하며 유효한 개선을 합칩니다. [적용 판단](../okf/adoption.md)에 따라 이번 범위를 정하고, [적용 안내](../APPLICATION.md)에 따라 이후의 자료 투입 위치와 반영 방법을 대상 저장소에 남깁니다. 사용자용 안내는 대상 README 등에 두고, 에이전트에게도 필요한 고유 선택은 선택한 지식 운영 진입점에서 연결합니다.
