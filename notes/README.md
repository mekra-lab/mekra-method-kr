# Notes

연구·관찰·질문과 판단의 배경·후속 기록을 둡니다. 채택한 운영 지식의 정본은 관련 개념과 적용 문서에서 관리합니다.

- 하나의 중심 질문이나 생각을 한 문서에 둡니다.
- 외부 사실을 적을 때는 출처와 확인일을 남깁니다.
- 채택된 결론은 `okf/`의 관련 개념이나 facet·version 문서로 옮기고, note에는 결정 결과나 연결만 남깁니다.

notes의 내용은 현재 운영 지침으로 간주하지 않습니다.

[적용 피드백](../okf/feedback.md)에서 아직 설명되지 않은 사례도 이곳에서 다룰 수 있습니다. 관찰한 사실과 해석을 구분하고, 공유 가능한 맥락과 피드백 출처를 남깁니다. 실험이 필요해지면 검증할 질문을 experiments로 연결합니다.

## 사례 대기와 보존 기록

- [자료 연결 방식과 선택 조건](corpus-connection-strategies.md) - 기존 접근으로 해결하기 어려운 실제 질의·갱신 사례가 생길 때 필요한 수단만 비교한다. 구현과 효과 검증은 미수행이다.

- [Personal context에서 드러난 지식 특성](personal-context-knowledge-properties.md) - 채택된 일반 판단은 관련 정본으로 연결했다. 남은 개인 맥락의 추가 요구는 자료·허용 범위가 마련되면 실험에서 관찰한다.
- [Facet 관점과 경계](facet-perspectives.md) - 분류 관점은 보존하되 독립 taxonomy 구축 과제로 두지 않는다. 실제 중복·탐색 실패나 고유한 판단 가치가 드러날 때 다시 본다.

문서의 존재가 실험 진행이나 결론 채택을 뜻하지 않는다. 대기 중인 질문은 재개할 사례가 생겼을 때 검토하며, 이미 정본에 반영한 판단을 다시 채택할 과제로 세지 않는다.
